# Quantum Builders Club: certificates and milestones

Claim a Quantum Builders Club certificate, or confirm Milestone 2 or 3, by opening an issue here with one of the forms below. A checker reads your public GitHub repos and runs the club's own tests against your code. Nobody reviews claims by hand: when every check passes, the certificate is issued automatically, with its own page on [quantumbuilders.club](https://quantumbuilders.club) that anyone can open to check it.

## What happens

1. You fill in the form: your name as it should appear on the certificate, and a link to each repo. Submitting opens a public issue.
2. The checker runs straight away and comments on the issue, with a ✅ or ❌ for everything it looked at. Ladder projects take a few minutes; pathway builds install their own requirements and take longer.
3. Anything ❌ says exactly what's missing. Fix it, push to GitHub, and comment `/recheck` on the issue (editing the form runs the checks again too).
4. When everything passes, the certificate is issued within a few hours: a comment with its link and a LinkedIn button lands on the issue, and the issue closes. Milestones are confirmed and closed straight away.

### Build Sprint Graduate

- The repo is public and yours (or in an organisation you're a public member of), not a fork, with a README.
- **Your goal:** your first push with a Goal section in the README (at least 8 words) starts your sprint. That's week 0, and each week is 7 days from that push.
- **Your weeks:** you pushed work to the repo (any branch) in at least 4 of the 6 weeks after week 0.
- **Your ship:** by the end of week 6, you pushed a README with a What I shipped section of at least 30 words.
- Only your own pushes count, at the times GitHub recorded them (the repo's Activity tab), so commit dates don't matter. A new sprint needs a new repo.

### Milestone 2: First Repo

- The repo is public and yours (or in an organisation you're a public member of), and not a fork.
- It has no GUIDE.md and no solution/ folder.

### Milestone 3: 3-Project Portfolio

- Three different projects from Projects 01 to 10, each recognised from its starter/ code, public and yours, with no GUIDE.md or solution/ folder.
- Each project's core test file from the club passes against your starter/ code, every test (for example 18/18 for Project 01).

### How the tests run

Each repo is downloaded and its tests run in a locked-down sandbox: a separate user with no network, on a fresh GitHub runner that's thrown away afterwards. Ladder projects run the club's copy of the core test file with `QBC_TARGET=starter` (the copy in `trusted/`, never the one in your repo), on Python 3.13 with qiskit==2.5.2, qiskit-aer==0.17.2, matplotlib==3.11.2. Pathway builds follow their build card: `pip install -r requirements.txt` (ready-made wheels only), the card's build script, then the tests. Before anything runs, the checker reads your code for tricks that could fool the tests and says which line if it finds one.

## Privacy

Issues here are public. Your GitHub username, your repo links and the name you type are visible to anyone, and the name is printed on the certificate. Your repos are listed on the certificate's page unless you tick "Don't list my repos". Never put an email address in an issue. To have a certificate removed, ask in the club.

## The rules

- The work is your own, and the repos stay public: the certificate's page links them.
- A certificate earned by fooling the checker is revoked, and its page says so.
